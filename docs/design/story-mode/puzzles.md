# 《余页》谜题册与墙外线索规范

> 完整答案／制作资料。配套 [故事大纲](./outline.md)。本文件中的命令、仓库线索和存档字段均为拟议设计，尚未实现；不要向用户声称现在即可运行。

## 1. 通用契约

所有必经谜题必须有：明确问题、可达证据、推理关系、操作、确定答案、可见后果、三级提示、手机等价路径和中断恢复。

三级提示随时可用，不用错误次数或等待时间解锁：

1. 告诉玩家还缺哪类证据、在哪个已开放场景。
2. 解释证据之间的关系，但保留一次自行判断。
3. 显示完整操作和解释，允许按该解释完成，不扣剧情资格。

解谜不测试记忆力、打字速度、现实编程知识或精确大小写。中文／全半角、首尾空格作合理归一化。选择题优先于任意字符串输入；自由笔记不参与正确性判定。

页签、控制台、真实重载和源码仓库必须分别有叙事作用，但不通过监视玩家是否真的打开 DevTools、访问外站来判题。理解证据后从任何等价路径作答都有效。

## 2. 顺序与依赖

```text
P00 调查教学 → P01 页签原名
                    ├─ P02 双址分卷（档案线）
                    ├─ P03 保存后重载（剧院线）
                    └─ P04 真实控制台（钟塔线）
                三线调查完成
                         ↓
                  P05 退稿与撤回
                         ↓
                  P06 真实源码仓库
                         ↓
                  P07 排演调用清单
                         ↓
                  P08 三案例验收
```

P02／P03／P04 不相互锁定。共同概念均由各自谜面提供最低说明；先完成另一线只增加追问选项，不是补救缺失线索。

## 3. P00：没有写目的地的票

- **位置／推理预算：** 序章，3 分钟。
- **问题：** 哪个站台对应票上的线路？
- **证据 A：** 票上三个孔形从左至右为圆、双横线、缺口方框。
- **证据 B：** 候车图例把它们分别标成白页站、版心街、城内换乘点。
- **证据 C：** 月台表列出 A 线先经版心街、B 线先经校样馆；不要求认识现实交通标识。
- **动作：** 先收票，再把票放到图例上比对，选择 A 线。
- **答案：** 白页站 → 版心街 → 换乘点，乘 A 线。
- **后果：** 打开调音室，学会物件／证据／地图之间的关系。
- **提示：** 找图例 → 对照孔形顺序 → 直接展示三站及 A 线。
- **等价／恢复：** 文字列表提供相同信息；不依赖拖拽、颜色或触控精度。错误可重选，刷新保留已收票据。

## 4. P01：装订签没有改口

- **位置／推理预算：** 版心街，8 分钟。
- **问题：** 维修单问“来稿中的桥名”，不是“哪一个名字在道德上更正确”。
- **证据 A：** 当前街头指示牌写“东桥”；白榆说地图经过统一校订。
- **证据 B：** 地图桌上的装订说明：“正文可以重排；装订签照抄来稿原名。此页的签在浏览器最上方的页签上。”
- **证据 C：** 该场景真实页面标题为 `西桥｜余页`。
- **推理：** 标牌是当前舞台，页签是明确指向的来稿索引。应填原名“西桥”，但不能据此推断东桥称呼没有任何出处。
- **动作：** 查看页签，在维修单选择“西桥”；然后可选择当前标牌是否附注俗称“东桥”。
- **完整答案：** 来稿桥名＝西桥。附注选择不影响判题。
- **后果：** 交通恢复，保留附注与否会影响地图桌的下一段争论，并持续到后期新地图；系统统一显示的其他缺句作为调查对象，不被包装成玩家明知的恶行。
- **手机／全屏等价：** 常驻故事工具提供“装订签抄本”，读取与该页标题相同的故事字段；桌面也可使用。抄本不是另一个答案来源。
- **提示：** 看装订说明 → 区分当前牌和来稿名 → “标题写西桥，选择西桥”。
- **恢复：** 章节内标题随场景设定，不依赖操作系统语言、现实日期或浏览器品牌。退出故事恢复正常站点标题；刷新不改答案。原标牌与原对白作为证据留档。

## 5. P02：一人为什么有两个有效地址

- **位置／推理预算：** 校样馆，6 分钟。
- **问题：** 四份记录应该按什么关系整理，才能不把两个版本拼成一天？
- **证据 A1：** 栞的街区来稿，地址“版心街 04”，版记为“街本”。
- **证据 A2：** 茶摊收件单，相同“街本”版记与上述地址。
- **证据 B1：** 栞的剧院来稿，地址“侧门 02”，版记为“幕本”。
- **证据 B2：** 剧院值班单，相同“幕本”版记与上述地址。
- **证据 C：** 授权柜说明两本均获准独立排演，没有一份撤销另一份的说明。
- **动作：** 将 A1／A2 放入街本，B1／B2 放入幕本；选择关系“不同版本，不强行合并”。标签可用预设，不要求自由输入。
- **完整答案：** 两组按版记分卷，均保留来源；不能按验收时间删掉一组，也不能把地址当作单次搬家推导不存在的经历。
- **后果：** 两个版本的栞分别得到入口。各自在之后的生活互动中有偏好和拒绝，不把此题变成选出真伪的人格测试。
- **提示：** 查看纸角版记 → 同版记录相互支持 → 展示 A1+A2／B1+B2 的完整分组。
- **等价／恢复：** 证据可点击后选择分组，无强制拖动；原始字样与图形标签均可朗读。错误组合指出哪份版记不符，不丢物件。

## 6. P03：布景回来，书签留下

- **位置／推理预算：** 无幕剧院，10 分钟。
- **问题：** 重开舞台后发生了什么，哪些材料仍然有效？
- **证据 A：** 排练台展示《暴雨夜·留桥》：“白榆留在折脊高架，协助封路。”状态＝来稿有效，版别＝排练。
- **证据 B：** 后台说明：“重新打开页面装入定稿；校听员已保存的书签不回到原点。”
- **证据 C：** 真实重载之后，舞台展示《暴雨夜·离城》：“白榆从白页站离城。”状态＝来稿有效，版别＝定稿。
- **动作：** 保存 A 的证据书签，确认保存成功，刷新；返回同一处，把 A 与 C 并排，选择关系。
- **完整答案：** 同一题材的两份有效、互斥来稿；此次载入改变了被展示的版本，没有证据表明先前来稿无效。既不能说白榆在同一晚同时做了两件事，也不能说玩家丢失存档。
- **后果：** 玩家掌握“当前显示不是全部事实”的实验方法。白榆会解释这是两份许可演绎，不指控玩家已经目击两个真实世界。
- **手机／PWA等价：** 提供“保存书签并重新开页”。可刷新时执行真正重载；环境不支持安全重载时明确标为“重开布景”，用同一故事状态转换完成对照。
- **提示：** 先保存排练书签 → 重开只换舞台，不改书签 → 展示两稿及“并列有效／互斥版本”答案。

### 重载状态规则

```text
未准备
  → 当前章所需资源可用
  → 排练证据持久保存成功
  → 标记待重返并提交检查点
  → 刷新或等价重开
  → 显示定稿，保留两份证据
  → 完成对照
```

- 任何保存失败都不能诱导玩家立即刷新；给出重试、导出与内存等价路径。
- 不按刷新次数判定，不要求某秒内回来，不监听 Ctrl+R 或推测浏览器导航方式。
- 如果保存后先退出，下次正常载入同样可以继续。
- 已完成时反复刷新停留在已完成状态，不反复切稿覆盖证据。
- 外网访问失败只触发真实的加载提示，不能伪装成故事中的报错继续推进。

## 7. P04：第五响不是没有到达

- **位置／推理预算：** 逆秒钟塔，9 分钟。
- **问题：** 钟楼需要修硬件，还是需要检查筛除规则？
- **证据 A：** 前台显示“第五响缺失”。
- **证据 B：** 抄时纸带记录第五响与第六响两次有效到达。
- **证据 C：** 维护纸条说明前台只报告排演结果，后台还保留收到但未上台的记录，并给出固定命令。
- **电脑动作：** 从浏览器菜单打开开发者工具的 Console，手打：

```js
window.yuye.inspect('clock');
```

拟议输出：

```text
余页／故事诊断，仅限本章
钟楼设备：正常
有效收到：第五响、第六响
当前排演：第六响
第五响未上台的原因：与最后验收版本不一致
```

- **推理：** 设备确实收到，不是丢包；“未显示”和“未到达”被前台混为一谈。
- **完整答案：** 故障分类＝版本筛除；证据＝两次有效到达；处理＝保留两份回声出处，检查版本关系，而不是无条件同时播放制造噪声。
- **后果：** 岑停止无意义硬件修理，随后必须向角色解释她对“持续播放”的执念，不能只发一把新钥匙。
- **手机等价：** 故事工具中的“诊断端口→钟楼→检查”，读取与控制台同一个受限查询，输出完全一致。
- **提示：** 维护纸条指向后台 → 对比“收到”和“上台” → 给出完整固定命令、操作入口与诊断结论。

### 控制台接口边界

- 命名空间在故事进入后才注册，退出后撤销；实现时先检查冲突，不覆盖已有同名对象。
- `help()`、`inspect('clock')`、`inspect('cast')`、`verify()` 均为只读查询。其他目标返回可理解的帮助，不接受任意路径／函数／脚本。
- 不自动改存档。查询证据与提交答案分离，最终提交在故事界面明确进行。
- 不教用户输入“允许粘贴”，不要求粘贴代码块，不让命令发送网络请求或读取登录信息。
- 不用控制台清空、刷屏或强制 `debugger` 打断；也不以浏览器 DevTools 检测代码作为任务条件。
- 新手不懂控制台时，图示解释浏览器菜单位置；直接走等价诊断端口也拥有完整故事体验。
- 命令拼错没有故事副作用；重复读取仍可获得同一证据。

## 8. P05：留下记录不等于继续营业

- **位置／推理预算：** 退稿水库，8 分钟。
- **问题：** 季当前的问候是否仍处于有效排演许可内？
- **证据 A：** 旧入库单允许排演书店问候，版记“初次来稿”。
- **证据 B：** 后来的退场单明确写：“停止全部排演，包括旧片段、匿名背影和临时补位；只保留一张允许展示的闭店说明。”
- **证据 C：** 水面投影是镜像排列，投影框却保留正向的版记；按版记还原顺序后发现问候调用发生在退场单之后。
- **规则说明：** 不以真实时钟比较先后；纸面序号／版记与事件链直接给出次序。
- **动作：** 对照投影原件，排列“入库许可→退场→旧稿被调用”，选择当前状态。
- **完整答案：** 旧许可已被后来的明确请求限制；当前旧稿调用违反退场要求。保留证据不是继续演出的许可。
- **后果：** 下一步目标从“把季救回书店”改为“查清谁仍在调她回来”。季的码头说明被写成她特别允许的一次告别说明，不借此取消整体退场请求。
- **提示：** 检查投影版记和退场单 → 旧许可与当前许可不同 → 给出事件链及“当前调用应停止”。
- **等价／恢复：** 镜像排列提供正向文本对照和点击式排序。声音、反射辨认或阅读倒字都不是唯一通道；全部证据入笔记，素材不在时直接给清晰的文字版。

## 9. P06：这座城为何只剩最后一份稿

- **位置／推理预算：** 页外机房，14 分钟；跨区准备、角色讨论另计对应调查／对话预算。
- **问题：** 哪条工作规则造成有效版本被隐藏？怎样修正而不混剪历史？
- **入口：** 维护台出示本项目源码仓库地址、冻结版本、三个文件类别和明确目录，不要求读整个项目。

### 拟新增的真实仓库线索

```text

  rights/bai-yu.txt

```

上述文件是明确标注的**虚构剧情资料**，不导入游戏运行，不伪装为维护者真实事故记录。本轮仅设计，不创建这些线索文件或提交远端修改。

`README.md`：

```text
《余页》第一版排演资料／虚构故事线索
来稿：发生了什么／属于哪一版。
授权：这些材料可以怎样使用。
工作规则：排演器实际上选了什么。
请在三个文件之间核对，不需要提交代码修改。
```

`records/rain-night.txt`：

```text
事件：暴雨夜
《留桥》：白榆留在折脊高架；来稿验收通过。
《离城》：白榆从白页站离城；来稿验收通过。
验收顺序：《留桥》在前，《离城》在后。
两份材料属于不同的许可演绎，不应拼成同一晚。
```

`rights/bai-yu.txt`：

```text
两份来稿均允许分卷排演，并须标注版本。
后验收不自动撤销先前授权。
以后另有明确限制或撤回时，须按新的授权状态处理。
不得把任一演绎当作公共设施现状的证明；路线安全需另行核验。
```

`runtime/collate.ts`：

```ts
// 虚构校订器说明，不在项目中执行。
// 同一事件，只选择最后验收版本。
export const sameEvent = 'retain-last';
// 更早版本不进入排演索引。
export const earlierEditions = 'hide';
```

### 推理与答案

1. 两份来稿均通过验收：不能用“其中一份无效”解释缺席。
2. 两份都获准分卷：不能用“后者撤销前者”解释缺席。
3. 工作规则只选择最后验收者：这才是隐藏发生的位置。
4. 即使分卷恢复，也不能把演绎里的留桥／离城当作当前交通安全报告。

**完整答案：** 来稿均有效且允许分卷 → 校订器使用 `retain-last` → 先前版本被 `hide`。修正为按当前授权建立带出处的多个版本索引，不自动覆盖，也不混剪为同一条历史。

**提交方式：** 回到游戏证据板，把“来稿有效”“授权不互相撤销”“工作规则只留最后一份”各放入一个槽位，再选择修订提案。答案不是从源码抄一个神秘字符串。

**后果：** 沙盘显示不同版本可以并存，但季依然被旧稿补位；玩家发现仅改这一条还不够。取得源文件并不授权玩家替任何角色决定继续演出。

### 手机、网络和发行版本

- 电脑正常流程是真实访问 GitHub 文件；手机可用 GitHub 移动页面。
- 所有设备都提供“源码阅览室”，显示同目录、同全文、同链接关系，不用一页总结直接给答案。
- 仓库网址以 `https://github.com/PhiGameRevive/PhiCommunityRevive/blob/<archiveRevision>/story-evidence/yuye/edition-01/...` 为格式。
- `<archiveRevision>` 是实施后真实存在的提交，不填虚构 SHA，也不让故事存档只依赖会变化的 `main`。
- 发版产物携带该线索集完整镜像和版本标识。外网不可用／提交不可达时使用同版镜像；GitHub 页面读取不要求账号。
- 不依赖真实 Issues、评论、提交者姓名、Star 数或社区行为，不能要求发 PR、联系维护者或安装 Git。
- 仓库未发布前，这条路线的验收必须标为未完成，不能在正式游戏给一个 404 链接充当谜题。
- 设计文档本身包含剧透，公开前应清楚标注；前端开源项目无法杜绝提前看答案，不以此加反作弊。
- 提示：读三个不同职责文件 → 对照“验收”与“授权” → 展示整条因果链和正确提案。

## 10. P07：她离开了名单，却没有离开调用表

- **位置／推理预算：** 版心街与页外诊断口，4 分钟；人物协商另计对话。
- **问题：** 为什么季已不在出场名单，书店仍播放她的旧问候？
- **证据 A：** 街角书店显示“店主退出排演”。
- **证据 B：** 当前故事排演清单：

```text
当前出场：栞、白榆、岑
旧稿补位：季／书店问候
已确认退场：季／全部排演（含旧稿补位）
允许留下：闭店说明
```

- **真实关联要求：** 清单必须来自决定此场景载入的真实故事状态，不允许硬编码一份与实际行为无关的假控制台截图。
- **动作：** 在故事存档阅读器查看清单；电脑可用 `window.yuye.inspect('cast')` 得到同样的只读内容。指出旧稿补位这一调用入口。
- **完整答案：** 当前名单已移除，但 fallback 仍调用季；应同时停止旧稿补位，保留她明确允许展示的闭店说明。
- **后果：** 玩家向岑提出诊断，岑亲自确认处理并撤销补位；重新进书店不再复演问候。不能让玩家无视季要求选择“多放一次”。
- **提示：** 不只看当前出场 → 检查补位 → 明确指出季／旧稿补位这一项。
- **等价／恢复：** 手机存档阅读器可选文字完整可读，不要求下载编辑 JSON。只是读取，不让用户改库；后续改变采用可恢复检查点。

## 11. P08：三份请求，不是一条万能规则

- **位置／推理预算：** 空白印场，8 分钟。
- **问题：** 提案是否真的分别尊重并列、改写和退出，而不把一种原则强加给所有人？
- **证据：** 第 7 章三条协商线的原文请求与实际执行记录，随时可回看。

**动作：** 将三项请求逐一转成试演规则，运行预演，对照结果，再确认实施。校订员给出有限席位约束，角色协商轮换／停演时段。

**完整答案：** 按当前授权分卷并列；署名改写、区分历史与现行；完整执行退出；活动席位以协商轮换处理，不以删除授权版本解决容量问题。

## 12. 谜题测试门禁

每题至少检查以下路径：

- 无提示自行解答、三级提示后解答、先猜中再补看证据。
- 所有有效三线顺序，不引用尚未学到的章节知识作为唯一线索。
- 键盘、鼠标、触屏、可选择文本／辅助阅读路径。
- 外网不可达、GitHub 打不开、控制台不会用、全屏／安装版隐藏页签。
- 在提交前、保存中、过场中、返回场景时退出或刷新。
- 存储不可用／空间不足／旧版存档，先保护进度再提供替代路径。
- 答案归一化，不被中文标点、全半角、大小写或空格误伤。
- 没有输出真实隐私、请求额外权限或修改非故事数据。
- 删除这道 meta 谜题后应缺少一条明确的主线推理；若不缺，应改成支线，不能占据必经时长。

关键测试问句不是“你输入了哪个密码”，而是“你为什么判断它被筛掉／没有撤回／仍在补位”。
