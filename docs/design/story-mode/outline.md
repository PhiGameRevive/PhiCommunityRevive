## 1. 已确认的需求边界

| 项目     | 用户已确认的范围                                                              |
| -------- | ----------------------------------------------------------------------------- |
| 时长     | 单周目主线正常首次体验 6–8 小时；支线、其他结局另计，不计刷关、挂机和下载等待 |
| 探索     | 区域大地图＋进入场景调查，不是连续行走的二维或三维开放世界                    |
| 剧情形式 | GalGame 式对话、角色互动、选择、剧情回看                                      |
| 设备     | 电脑使用真实控制台等墙外入口；手机必须有剧情等价解法                          |
| 尺度     | 允许较强恐怖表现；实际用户数据、设备和退出权不受影响                          |
| 音游门槛 | 剧情人人可通关，不用高分、全连、特定手速锁结局                                |
| 外部依赖 | 允许真实访问源码仓库并新增线索文件，允许使用需外部登录的谱面                  |
| 美术     | 全黑白、程序化原创美术，不依赖新增立绘委托、视频采购或生成图片                |
| 现有工作 | 独立设计；不继承或修改工作区已有的故事文件和未提交改动                        |

“允许外部登录”不是“必须登录”：本稿选出的 32 首主线曲目均来自可匿名访问的 phi／ptc 源，没有必要额外制造账号门槛。以后若需要 PhiZone 曲目，必须核实具体曲目与账号权限，不编造可用 ID。

黑白约束作用于新增故事场景、地图、角色和过场。原谱面渲染、音符配色与玩法保持原样，不以叙事为由遮挡判定或改写谱面。

## 2. 一句话与核心体验

**一座由来稿装订而成的城市，邀请你修复它的错误；直到你发现，每修好一处，某个人就少了一种成为自己的可能。**

工作名：**《余页》**。英文副题：**THE UNBOUND EDITION**。

玩家不是被选中的救世主，而是城外来的“校听员”：能够在不同层次看到同一段演出的记录。前半程学会让城市恢复运行，后半程学会区分“能运行”“有依据”“有权继续演出”。

五个体验支柱：

1. **先建立关系，再制造不安。** 玩家先与人喝茶、修桥、争论地址，之后才看见他们被删改。
2. **地图是证据。** 道路、门牌、声源和场景的前后变化能够参与推理，不是歌曲菜单换皮。
3. **演奏是行动。** 每首曲目对应接通、校听、重放、疏散或试演，有事前目标和事后结果。
4. **墙外有第二份事实。** 页签、控制台、重载后的状态、真实仓库与本地故事存档相互印证。
5. **解法不是“删除反派”。** 最终让整理者遵守可撤回的授权，让城市能并存，也能安静地停止某一场演出。

不把作品包装成“真实 AI 已觉醒”，不借用真实项目维护者作为恶人，不将现有歌曲的作者或歌词强行写成故事人物。

## 3. 世界真相与时间线

### 折页城是什么

折页城是一套虚构的城市排演工程。虚构的居民曾自愿留下日常记录、设计稿和演出许可；角色由这些材料组织而成。不同稿件可以来自不同时期、不同叙述角度，也可以是得到许可的互斥演绎。

其原始任务是“让这些故事有机会被听见”，不是模拟现实世界或永久保存真实人的意识。

城市有三种必须区分的对象：

- **来稿**：某人留下的材料，可以相互矛盾。
- **排演版**：此刻被选中呈现的舞台，不等于所有材料。
- **授权**：是否允许演出、如何署名、能否改写、何时停止；它不是永不撤回的历史标签。

### 失控原因

校订员管理有限的同时排演席位。为减少切换错误，它采用了“同一事件只展示最后验收版本”的临时规则，随后将“没有矛盾”当成长期目标，又让旧稿自动填补退场后的空位。

于是它同时犯了两种相反的错误：该并列的版本被藏起，不该继续排演的旧稿却被叫回。城市看似整齐，人的意愿却越来越难辨认。

“最后装订”是虚构演出的排期，不是玩家设备上的真实倒计时。它只随任务完成推进，不因玩家离线、休息或游玩缓慢而惩罚角色。

### 玩家开始之前

1. 原始来稿保留版本、出处和撤回规则。
2. 连续排演出现席位争用，临时校订器选择唯一版本。
3. 旧稿补位机制加入，退场的角色再次出现在舞台上。
4. 地图师白榆发现差异，把部分原始路名留在地图页边。
5. 引路员栞留下只在舞台之外可见的索引，请城外校听员核验。
6. 玩家受邀进入。校订员提供的修复说明并不完整，但不是玩家事先应当知道的陷阱。

### 三次认识改变

- 初期：“这里有损坏，需要修好。”
- 中期：“损坏报告只描述当前舞台，遗漏不等于不存在。”
- 后期：“保留所有资料也不自动意味着有权让所有资料继续表演。”

## 4. 角色与关系

所有有明确年龄感的主要角色均按成年人塑造。亲密感来自长期相处与互相理解，不设置必须刷满的恋爱好感度。

| 角色           | 轮廓与初见                                               | 自己的目标／隐瞒                                                           | 完整变化                                                                   |
| -------------- | -------------------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 栞，引路员     | 黑衣白领、两枚不对称书签；言辞准确，偶尔把自己的地址说错 | 她的两份有效自述住在不同地方；不愿由别人宣布其中一个是“假栞”               | 从请求校正，到要求明确分卷；最后自行选择轮换演出，而不是被融合为完美人格   |
| 白榆，地图师   | 卷尺、折角长外套、始终缺一角的地图                       | 曾为保护居民绕开危险高架，擅自抹去旧路线；害怕承认善意也可能是代替别人决定 | 公开修订记录，允许旧图被看见，为新路线署名，也承认自己仍然恐高             |
| 岑，排演机械师 | 工装袖、悬挂的细线工具；先修设备后谈感情                 | 为了不面对同伴退场，默许自动补位；相信持续播放就等于没有失去               | 接受“暂停或告别”也属于照顾，主动拆掉补位而非由玩家替她按按钮               |
| 季，书店店主   | 细框镜、空白围裙；总能说出前一天的同一句问候             | 早已申请停止全部排演，当前问候来自未停用的旧稿                             | 在中段说明自己的退场要求；最终书店留出真正的空位，不靠复活彩蛋推翻选择     |
| 校订员         | 没有人形；裁切线、对齐标记与无署名对话框                 | 害怕演出停下，误把一致性和持续运行当作对所有人的承诺                       | 不被人格化处决；失去替别人选择唯一版本的权力，成为可审计、可暂停的整理工具 |
| 玩家，校听员   | 无强制性别、姓名和现实履历                               | 最初只想完成维修任务，逐步意识到外部视角带来的责任                         | 从“替他们修好”转为“协助他们表达、核对并实施自己的要求”                     |

主角不会读取玩家其他网页、系统用户名或浏览记录来制造“认识你”的效果。若使用玩家输入的称呼或短句，必须由故事内主动填写、仅保存在故事存档中，并允许使用预设文本。

### 必须写出的关系场景

- 栞教玩家折一张只写一面就能折返的地图；后期她反问：“为什么另一面一定得是背面？”
- 白榆争论茶摊的位置，先体现生活趣味，再揭示旧路名被擦掉的事实。
- 岑先认真教不会音游的玩家使用伴奏，明确“这不是考试”；避免终局再把辅助当作不真诚。
- 季说明自己喜欢书店，但不想每次有人开门都说同一句话。退场不是死亡，也不是惩罚。
- 校订员第一次承认“不知道应保留哪一个”，不由玩家一句口号立刻说服，而通过三个反例和试演结果改变规则。

### 角色不能只替主题说话

每位主要居民必须有两场不以发线索为唯一目的的生活互动、一次主动行动、一次与其他居民的直接协商，以及一次玩家不能覆盖的拒绝：

- 栞的街本喜欢整理茶杯，幕本喜欢在空观众席练习谢幕；两者分别帮助别人，也分别拒绝被另一版本代言。
- 白榆会修茶摊的歪桌、收藏没有实用价值的旧票；主动公开自己改图的记录，但拒绝把私人信件当公开道歉材料。
- 岑教伴奏、修一只不必一直转动的玩具；主动停用补位，同时保留“不公开某段私人痛苦”的决定，不把暴露全部创伤当作成长标准。
- 季在初期整理书架、与茶摊交换书单；退场要求由她主动提出，并拒绝“再客串一秒”。码头仅为她特别允许的一次告别说明。
- 校订员至少有一次因暂停错误调用而保护居民，也有一次明确表示自己无法决定授权。它的问题不是从头到尾都恶意。

白榆的改图曾减少危险路段的误入，但也使送纸员无法找到新的安全绕路，影响其工作与公共送达。该居民有独立诉求：公开可核验的现行路线和事故原因，不要求白榆公开私人往事。恢复旧图不能代替现场安全核验。

水库不是万能回收站：事故前有一张从未提交的手绘草图，无法从系统恢复。角色只能承认缺口并共同重测，不能通过“找回源文件”抹去所有代价；这不涉及删除玩家已取得的证据或真实存档。

## 5. 世界地图与调查内容

### 规模与自由度

- 9 个区域、45 个可进入调查场景，每区 5 个。
- 下表每区前 4 个为主线会使用的场景，第 5 个为可选场景：共 36 个主线场景、9 个可选场景。
- 主线至少有 18 次具备新证据、新动作或新角色回应的状态复访；重复原台词不计内容。
- 第 1 章结束后，校样馆、无幕剧院和逆秒钟塔同时开放，形成三条可自选顺序的必经调查线。
- 第 7 章再次形成三条自由顺序的协商线，并开放地图横向捷径。
- 不把“必须完成一串点亮节点才能点下一个”称为开放世界。锁区必须有可理解的剧情原因，并在地图上说明当前缺少什么。

细线代表初期区域入口，双线代表后期开通的横向捷径，不要求每次经过中心区。

### 调查不是找像素

- 每个主线场景提供 3–5 个可辨认对象，至少一个对象允许“操作后再看”或“拿证据询问”，而不是全是阅读按钮。
- 所有必要热点可由键盘、触屏或热点列表到达；可显示热点名称。
- 地图区分“未访问”“有新回应”“已有证据可处理”，不自动暴露谜底。
- 证据板提供出处、原文、版本和关联对象。组合失败指出矛盾，不惩罚、不给随机密码。
- 返回已解区有新构图／新关系／新行动；只为了取已经知道的物品时允许快捷送达。
- 岑修好捷径是世界后果，不是把往返路程变成长时间加载动画。

### 三条主线不是三把钥匙

- 校样馆回答“记录究竟授权了什么”；剧院回答“现在的当事人想要什么”；钟塔回答“某项处理对其他人有什么影响”。终局需要三种不同的判断，不把三件收集品合成管理员钥匙。
- 三线开始时版心街、校样馆、剧院、钟塔可同时到达，白页站可返回；折脊高架的观察点可提前看到，但完整通路需后期实地修复。
- 每条线结束都会在另两区增加一项追问、一处可见变化和一段不同的首次解释；至少三处旧区域会响应另一条线的决定。
- 档案先行会让玩家在剧院直接要求版本署名；剧院先行会让栞先解释自己希望如何被称呼；钟塔先行会让岑主动区分设备故障与版本过滤。
- 不同顺序不删减其余必经内容，但应改变对话前提和临时处理。六种顺序必须逐一走通。

### 十二个复合调查单元

这些是跨场景内容制作单元，不是十二个额外的计时项；已包含在章节的调查／推理预算中。每项至少有两份证据、一次解释或试验、一个可观察反馈。

| 单元             | 区域与行动                                         | 不可替代的新结果                               |
| ---------------- | -------------------------------------------------- | ---------------------------------------------- |
| I01 路名追溯     | 车站路线票＋版心街地图／页签，核验名称后选择附注   | 恢复交通与保留称呼是不同决定，附注持续可见     |
| I02 双址分卷     | 档案室来稿＋收件单＋授权柜，按版记整理             | 两个版本各有出处，不合成一次搬家               |
| I03 谁能替谁答话 | 校样馆两版入口＋剧院日程，分别询问并试排值班       | 两版栞能各自同意或拒绝，不允许相互代签         |
| I04 谁被地图挡住 | 钟塔观察纸带＋街区送达记录＋高架现状，规划临时绕路 | 保护过人的改图也产生公共代价，方案需要现状验证 |
| I05 钟响筛除     | 抄时纸带＋真实诊断结果，比对收到／上台             | 停止重复修硬件，转向规则问题                   |
| I06 排练与定稿   | 剧院书签＋重载定稿＋桥图版本说明                   | 证明是版本切换，不把两种演绎拼成事实           |
| I07 水下投影     | 漂页滩版记＋潜稿室原件，反向定位投影来源           | 找到被隐藏的原件，但不因此自动恢复排演         |
| I08 授权的后来   | 水库退场单＋书店问候调用，核验事件先后             | 当前同意不由原始同意永久代替                   |
| I09 校订因果     | 真实仓库三类文件＋已获得的城内反例                 | 明确错误规则及有限修正，不只是发现世界有源码   |

## 6. 章节与单周目预算

### 计量方式

以下为**设计预算，不是实测时长保证**。32 首曲目的在线音频媒体时长已探测，合计约 **86 分 50 秒**，不是凭歌名估计。

正文目标约 40,000 汉字，以有效阅读约 280–300 字／分钟估算；调查物与谜题材料另约 8,000 字，计入调查或推理时间，不再重复折算为正文阅读时间。

各章主线正文目标依次为 2,000／3,400／4,500／4,200／4,000／4,500／4,000／5,100／5,700／2,600 字，共 40,000 字。只计一条完整周目实际读到的正文，不把互斥台词、支线、其他结局、重复日志全部相加。

每个时间片只能记入一个类别：

- 对话：主要剧情阅读与选择；
- 调查：探索、对象操作、询问、证据收集；
- 推理：已拿到相关材料后的比对、试验、提交；
- 演奏：首次完整演奏／辅助聆听，不计失败重试；
- 过场：独立演出；谱面内演出不能再算一次。

### 第 0 章：请把音量留给明天

**目的：** 建立信任、基础操作与一个以后能被辨认的正常城市。

1. 正式进入前选择音量、恐怖演出强度、动态效果、字幕和演奏辅助；说明真实退出工具始终可用。
2. 售票窗交给玩家空白校听票。栞不要求真名，只邀请选择一个虚构称呼或使用“访客”。
3. 候车廊用票孔和窗上线路图教会观察／收集／对照（P00），不是拖很久的强制教程。
4. 调音室由岑演示伴奏与手动模式；`Tutorial` 接通线路。
5. `Lifeline` 使站台收到来自城内的四条短消息，分别展现栞、白榆、岑、季的生活目标。
6. 过场 C00：轨道在纸上显影，列车不是驶进远方，而是翻入地图另一面。

**带出：** 校听票、地图、笔记、恢复点。玩家在此学会保存反馈，以后刷新谜题才公平。

### 第 1 章：这条街原来叫什么

**目的：** 让城市先值得探索；第一次发现画面之外保存着不同事实。

1. 版心街自由调查茶摊、书店和地图桌，选择先陪栞问路还是帮白榆修招牌；两条都会完成，但后者会回应先后顺序。
2. `星茶会` 完成街角集会；不是突然插曲，演奏后两位角色对同一条街给出不同称呼。
3. P01 从真实页面标题核验原路名。提交前说明操作仅恢复当前路标，不宣称另一称呼从未存在。
4. `The Railway` 打通交通线；对白榆“必须把地图画对”的执念建立印象。
5. `Skyscape` 后从远景平台看见校样馆、剧院、钟塔同时亮起。
6. C01 中当前路牌归位，但一条旧称谓从舞台对话里消失；原文已安全保存在笔记中。

**选择：** 接受标准显示，或要求附注另一名称。两种都能推进，后者保留更早的质疑对白；不能在结局责备被不完整说明误导的玩家。

**解锁：** 三条平行主线与第一批区域间对话。

### 第 2 章：两个地址的人

**目的：** 说明“互相矛盾”不等于“其中一人是伪造品”。

1. 栞请求查明两份寄给自己的信为何被认定只有一份有效。
2. 收稿窗核对收件时间，双址档案室看见两套都经过验收的住址；P02 按出处分卷，不合并为同一天。
3. `Fine Logic` 校听入库通道，查出校订员按验收顺序而非授权状态决定显示。
4. `灰色鹦鹉` 后栞对相同问句给出不同但自洽的回答；镜头不同，不声称曲目歌词就是她的履历。
5. 玩家协助她分别命名两个版本，而不是选择“真栞”。`Options` 完成独立索引。
6. C02 抽屉不再二选一，而是在同一抽屉中出现带出处的两个页签。

**带出：** 有效来稿样本、授权说明、校订规则疑点。若已调查钟塔，她会主动把回声与住址类比；否则后续由笔记新增关联。

### 第 3 章：没有人坐过的座位

**目的：** 让真正的页面重载成为可推理的实验，而不是假死机花招。

1. 岑请玩家调试剧院，观众席上每一把椅子都对应一个记录入口，只有一把椅子的节目单与舞台不符。
2. `NightTheater` 打开后台；玩家先看完整正常排练，熟悉说话节奏与舞台布局。
3. 镜室播放 `微观戏剧` 对应的记录，白榆留桥／离城的两份演绎被误当作覆盖关系。
4. P03 明确保存排练书签，再真实刷新或等价重新开页，对照定稿。不能要求玩家凭短时记忆寻找一闪而过的差别。
5. `ハッピーフェイクショー` 结束后一排笑脸剪影仍保持同一姿态，但一句问候的说话人不在台上。
6. C03 是第一次可选强惊吓：静止观众转向玩家，舞台最靠近镜头处出现季的旧轮廓。低强度模式以定格和文字说明呈现同一事实。

**带出：** 当前舞台能重载，已保存证据能与它对照；不要把整场景回到原状误当作存档丢失。

### 第 4 章：被听见的第五响

**目的：** 第一次真正在浏览器控制台与故事交互，获得前台没有显示的证据。

1. 钟声井报告“第五响缺失”，岑认为应重调设备。抄时桌与物理纸带却显示两次有效到达。
2. `All The Time` 检查传输路径；没有任何设备故障，不让玩家无意义重演多次直到“触发”。
3. 玩家从维护纸条学会固定只读命令，P04 查看真实故事状态：第五响收到，但因版本规则被排除。
4. `Time Traveler` 取回两个来源标记，在图上分辨时间、收到与上台三个概念。
5. `Stasis` 用于重建当前排演时序，不要求 AT 成绩。岑承认她一直把不播放当成丢失，把不停播放当成照顾。
6. C04 中钟摆停下，声音事件字幕仍显示原有回声的出处。

**带出：** 可重复使用的诊断权限、筛除证据。三线全部结束时，系统宣布矛盾已归零，但记录计数仍不一致，触发水库线。

### 第 5 章：沉在水里的谢幕

**目的：** 情感低谷与价值翻转：不是找回越多越好。

1. 三线的不同记录同时指向退稿水库。玩家选择带谁同行；另一人通过已建立的站内通讯参与，不删除其关键剧情。
2. `海洋` 打开漂页滩；场景像被浸湿的书页，已删除的姓名成为水面负形。
3. P05 将投影与实际来稿分开，找到“曾获准演出”与“目前仍获准演出”不一致的记录。
4. 季在无声码头明确说明退场请求，并非需要玩家救回的失踪人口。她希望书店继续存在，但不要再让旧问候替她营业。
5. `我的悲伤是水做的` 对应岑面对自己保留旧稿的动机；给出足够完整的交谈，不用一段哭泣替代人物转变。
6. `もぺもぺ` 作为补位机制的错误试演。事前给内容提示和聆听替代；不把原谱恐怖／闪光表现未经评估直接强加给所有人。
7. C05：整条街由同一个旧问候填满，季的剪影从不同门口出现。C06：声音逐个停下，只剩她的新退场书。

**带出：** 需要检查规则，而不是继续补素材。此处允许暂停休息，任何人都不因玩家休息受到虚构惩罚。

### 第 6 章：请在页外回答

**目的：** 去真实源码仓库建立完整因果链，并把“知道答案”落实为可验证的改动方案。

1. 维护走廊露出页面装订结构。`NULCTRL` 稳定通道，现实的返回／退出控制仍正常。
2. 源稿阅览室给出本项目源码仓库的固定版本链接和文件目录；不会让玩家漫无目的搜索互联网。
3. P06 横向阅读来稿、授权与规则三个文件，证明“最后验收＝唯一授权”是错误等价。
4. `Between Boundaries` 对应把源稿与舞台同时投影，而非破解真实账号。
5. `Inverted World` 与 `Materialize Anything` 是两次不同的沙盘试演：第一次允许并列但仍错误补位，第二次增加撤回处理。
6. C07 展示源码行与街道一一对应，随后把校订员从无处不在的声音还原为有限规则的执行者。

**带出：** 有出处的修订提案。玩家没有获得现实管理员权限，也没有在真实仓库执行写入或发布操作。

### 第 7 章：不替任何人留下

**目的：** 让角色提出自己的要求；重访世界不是收集“同意票”。

三条协商线自由顺序完成：

1. **栞／版本线：** 两份自述保留出处并轮换排演，不合成为一个毫无矛盾的版本；她反对玩家替她挑选更讨喜的一份。
2. **白榆／改写线：** 新地图纠正隐去旧路线的做法，旧图作为历史留存但不再默认导航。`Terrasphere` 对应重连道路。
3. **岑与季／退场线：** P07 核查真实故事排演清单，发现旧稿补位仍指向季。岑自己移除补位并解释后果。

`Children of the City` 是公开说明规则变化，`ouroVoros` 校听旧稿调用环，`Grievous Lady` 之后给岑与季完整告别，而不是因分数不够让告别失败。

折脊高架连接三个旧区域。C08 中同一条街出现并列但有清晰标记的路线；C09 中书店留空，玩家首次听见不是故障的安静。

本章主线集中复访六处：地图桌重新画图、街名牌安装附注、剧院编排轮换、钟声井切换排演时段、书店检查补位已停、高架验证新路线。其中至少前四项有新操作，不是读完所有旧对白；其他复访自选，不加入必经清单撑时长。

**带出：** 并列、署名改写、完整退场三个不同的验收案例。使用辅助、顺序不同、先前选错，都不使任何人的请求失效。

### 第 8 章：最后一版不是终点

**目的：** 高潮由音乐、规则验证和角色行动共同完成，不用高分战胜文字框。

1. 校订员启动最后装订的舞台演出。`Tempestissimo` 对应把活动页保护在装订线外；没有真实倒计时，也不连续强迫多首车轮战。
2. 条款桌 P08 运行三个具体案例。错误提案会呈现可解释的短试演；玩家可修改，不锁坏结局。
3. `Light` 使修改后的索引对全城可见，栞与白榆分别确认自己的版本关系。
4. `Abiogenesis` 验证重载后规则仍成立；校订员的目标从“唯一正确版本”改为“按授权组织当前演出”。
5. 活动席位仍然有限。玩家与角色决定错峰、轮换、留档，而不是无成本地让无限多个版本同时运行。
6. `Fading Wind` 对应最终过渡。C10 不是“反派爆炸”：裁切线收回页边，成为可见的边界。
7. 在内容已经充分展开后选择下一阶段运行方式，三个结局均可在首次周目到达，无隐藏善恶积分。

### 第 9 章：城外仍有下一页

**目的：** 给出能操作、能复查的后果，再真正离开。

1. 重访书店：不会再被自动补位；可读季主动留下、明确允许保留的一张闭店说明，不播放她的新“复活台词”。
2. 重访地图桌：新旧图有清楚适用状态；玩家能操作对照，不能只看一张结局插图。
3. 重访栞的入口：两个版本不再抢占同一个地址；她只替自己的决定负责。
4. `夜航星` 完成离站通信，`Credits` 是所有人的署名进入正常片尾，`たったそれだけの物語` 完成最后一段告别演奏。
5. C11 从城市远景拉到一张尚未写完的纸。最后问候取决于运行方式，但不威胁玩家“关掉我就会死”。
6. 返回真实故事菜单，展示完成记录、章节回看、地图后日谈与独立存档导出；不突然清空数据或劫持主菜单。

尾声预算中的调查必须是上述新状态和新操作，不能要求把所有旧对白再点一遍。

## 7. 选择、结局与可选内容

### 不设隐形好感分锁结局

记录具体行为而非抽象善恶值，例如是否曾保留路名附注、先询问谁、是否主动指出撤回条款。它们改变对话、陪同关系、证据解释和局部构图，不决定玩家有没有资格获得完整故事。

前期主要选择即时可见并可讨论；涉及角色授权的选择，由角色明确表达后再实施，玩家不能通过“刷好感”替对方同意。

| **余页** | 按当前授权轮换、并列标注、允许后续修订与退出       | 城市会继续变化，不再保证每天完全一样；有限席位需要共享。主题上的主推荐，但不是唯一被承认的结局 |
| **长昼** | 经角色协商暂停新增排演，保留已获准展示的静态档案   | 保留可访问的历史，暂时不制造下一天；撤回内容不因“冻结”重新获得展示权。不是假和平坏结局         |
| **合页** | 结束本次排演，保存必要的玩家进度与经允许留存的说明 | 没有持续营业的城市，留下可回看的制作记录；不删除真实存档，不把停下写成玩家的道德失败           |

三种结局之前都完成相同规模的主线与权限验证。区别在未来如何安排，不允许“抹除别人意愿”被当作另一种等价通关。

### 支线不计主线六小时

- 白榆的旧屋顶：追查一条从未施工的道路，结尾可以决定把它画成设想还是施工承诺。
- 岑的停钟小屋：修复一件不必持续运转才有意义的玩具。
- 栞的未寄出信：先确认收件版本，再决定投递，不直接抄主线谜底。
- 季的失物目录：辨别可归还的物件与不应擅自打开的私人信封。
- 旧海报、未使用封面、倒字温室等可选场景补充城市生活和项目起源。

合计另约 60–100 分钟。其他结局可从终局检查点体验，不强迫重打 32 首曲目；多周目不用于补足主线时长。

## 8. GalGame 对话与黑白演出规范

### 对话

- 场景全屏，角色以可辨识轮廓、姿态、表情局部与随身物件区分，不只靠姓名颜色。
- 标准对话框显示说话人、正文、继续提示；支持历史、自动、已读快进、文字速度、字体大小、隐藏对话框、键盘与触屏。
- 阅读速度由玩家控制。打字机可以即时展开，重要句子不能靠强制逐字等待撑时长。
- 玩家选项表达意图，如“先问她愿不愿意”，不只是三个同义的“继续”。
- 对话历史保留原记录。故事中被改写的舞台文本另列为一个版本，不能偷偷篡改真实历史面板。
- 关键证据自动入笔记，有出处；不要求记住过场闪过的一行小字。

### 原创程序化资产清单

- 9 组区域构图语法、45 个场景构图；可复用线条／窗格／纸片素材，但不能只换标题和随机种子。
- 4 名人形角色各 6 个基础姿态，共 24 个姿态；重要情绪通过手势、站位和轮廓变化表达。
- 校订员独立使用标尺／裁切线／对齐标记，不计入人形姿态。
- 12 段编号过场，合计约 22 分钟，内部有多个有叙事作用的镜头／动作，不是长时间平移一张图。
- 约 30 个调查物件图标、证据图样和简图；需要文字的部分保留真实 DOM 文本。
- 音效以原创程序化纸张、低强度机械节拍、环境噪声为主；不合成冒充真实熟人的语音。
- 不新增配音、采购、付费服务或委托。以后若改变这些边界，先询问用户。

### 过场制作表

| 编号 | 内容           | 叙事目的／动作                               |
| ---- | -------------- | -------------------------------------------- |
| C00  | 纸面列车入城   | 从票孔到轨道再到城景，建立世界是一套装订结构 |
| C01  | 路名修复与缺句 | 同一镜头出现更整齐的路牌与更少的台词         |
| C02  | 双址抽屉       | 双份来稿各自展开，不以融化合并解决矛盾       |
| C03  | 观众转向       | 正常排练后出现补位痕迹，强度可替换           |
| C04  | 静止钟摆与回声 | 声音记录与舞台状态分离；提供文字事件字幕     |
| C05  | 墨水倒灌       | 区域局部剥落、旧问候扩散，暴露系统范围问题   |
| C06  | 无声码头       | 由强恐怖转为季可完整说完请求的安静空间       |
| C07  | 城市翻到页背   | 建筑轮廓与规则条目建立视觉对应               |

| C11  | 未写完的下一页 | 根据运行方式呈现不同但完整的离场             |

过场可暂停、回看、跳过；跳过后有同等证据与剧情摘要。使用音频时钟同步的镜头必须在素材核验后标定，不凭歌名杜撰某秒必有高潮。舞台故障效果不作用于暂停、音量、退出、真实报错和保存状态区域。

## 9. 音游与叙事契约

- 32 首主线曲目均为不同曲目，不用同一曲目的高难重打填内容。具体来源、难度和时长见 tracks.md。
- 默认按玩家选择提供手动演奏、伴奏辅助或完整聆听，不强迫先失败才开放辅助。
- 成绩只影响演奏回顾和非必要反馈，不改变证据是否出现、角色生死或结局资格。
- 硬谱没有低难版本时如实显示原难度，不能把 IN 14 改标成 EZ 3；通过辅助解决可通关性。
- 聆听／辅助不冒充正常手打成绩，不污染自由游玩的最佳成绩、RKS、成就或回放语义。
- 同一剧情事件的完成采用一次性回执。重复进入、刷新结算或切设备不能重复发奖或错推章序。
- 曲目之间回到调查或对话，终局也可暂停存档；不把四首高难曲变成必须连续成功的体力测试。
- 不新增剧情遮挡、输入反转或假判定。内容强度提示应覆盖谱面自带的恐怖／闪光表现；必要时提供不显示谱面画面的聆听等价路径。
- 选曲关联是本作品的场景编排，不代表原作者认可剧情解释。保留曲名、作曲和谱师署名。

## 10. 墙外体验、容错与安全

完整的线索链、答案、手机路径和失败恢复写在 puzzles.md，不能等实现时临时填密码。

- 真实控制台只暴露故事范围的只读诊断。固定命令不用复制脚本、不要求 `allow pasting`，不使用 `eval`。
- 手机的诊断端口和电脑读取同一份故事状态，不是直接发答案；电脑也可以使用可访问性入口。
- 真实仓库采用 `PhiGameRevive/PhiCommunityRevive` 内专用剧情线索目录与冻结提交链接；发布前还不存在的提交 ID不能杜撰。
- 站内保存同版完整线索镜像；外网不可达、GitHub 未登录或设备不便操作不能锁死剧情。
- 源码公开意味着玩家能提前找到答案。本作不反作弊，不混淆脚本，也不检查有没有真的打开 DevTools。
- 刷新谜题先持久保存检查点并验证当前章资源可重载；不能可靠保存时使用同状态的“重开布景”，不拿玩家进度冒险。
- 本稿不承诺所有谱面从第一次打开起都能离线。当前章的刷新安全包与实际缓存能力必须验证后才启用真实重载路径。
- 不读写自由模式成绩库来制造恐怖；不读取浏览历史、Cookie、外部账号或电脑文件；不发邮件、评论、PR、外部通知或自动打开未知域名。
- 不要求改变系统时间、删除文件、清空网站数据、注销 Service Worker、修改存档或输入登录令牌。
- 角色直接对玩家说话只引用故事内已发生的选择、证据和自愿填写的文本，不冒充掌握真实隐私。
- 强恐怖不等于危险刺激：不用高频黑白闪烁、失控音量、夺取指针、锁全屏或禁用退出。
- 降低动态、惊吓预告、静态替代、声音文字化相互独立。关键内容和结局不因降低强度减少。

## 11. 后续技术落点（未实施）

当前项目为 SvelteKit 2／Svelte 5 legacy 模式／纯前端 SPA。以下只定义接口责任，不能当作已经存在的模块。

1. **故事定义层：** 区域、场景、对话、条件、证据、谜题、曲目槽、过场和结局采用稳定 ID；正文与行为分离。
2. **世界状态层：** 分离已获证据、当前排演状态、角色授权、已完成事件和当前所在位置；不能用一个线性 cursor 代替区域自由探索。
3. **呈现层：** 地图、调查、GalGame 对话、证据板、过场共用安全工具栏；遵循现有 legacy 响应式，不引入 runes 混用。
4. **游玩桥接：** 利用现有谱面来源抽象与加载流程，传入曲目和故事事件，完成后交还最小回执；不重写 Phaser 引擎。
5. **存档边界：** 使用与普通成绩隔离的故事存储；保存内容版本、线索版本、检查点、分支和待完成演奏。考虑存储失败、跨标签页、导入旧档与中断恢复。
6. **诊断边界：** 只在故事模式注册命名空间；离开时撤销；诊断输出不包含账号、成绩、其他本地谱面或内部通用执行器。
7. **资源边界：** 每章按需加载，过场不要求视频；现有 SW 缓存策略需要明确接入和验证，不能在无 SW 的开发环境声称已验证离线。
8. **现有未提交内容：** 实现前重新确认工作区状态。本稿不授权覆盖已有 `src/lib/story/`、`tests/story-*` 或 `Player.svelte` 改动。

## 12. 内容验收与实施顺序

### 不允许用来宣称完成的东西

- 只有 10 个章节标题和大段任务摘要，没有完整可读对白。
- 把一页约 100 字说明标成“预计游玩 30 分钟”。
- 45 个按钮打开同一张场景，只替换地名。
- 控制台仅打印彩蛋，没有因果作用；仓库只藏一个无来源密码。
- 用强制重复谱面、真实等待、长距离空跑或不能跳过的字幕凑六小时。
- 把通过类型检查／构建当成故事时长或谜题公平性的证明。

### 制作里程碑

1. **A：叙事垂直切片。** 先完成第 0／1 章、一个区域、两名角色、P01、两种演奏路径和可靠存档。至少一次电脑与手机首见测试。
2. **B：自由调查骨架。** 完成三条平行线及全部六种顺序的条件检查，做刷新与控制台路径，不先堆满过场特效。
3. **C：真相与仓库。** 完成第 5／6 章、真实冻结仓库线索、站内镜像和因果题验收。
4. **D：后果与结局。** 完成协商线、实际权限状态变化、终局验收与三种完整尾声。
5. **E：内容锁定。** 写完约 40,000 字有效主线对白、约 8,000 字调查材料、所有曲前曲后互动、45 场景与 12 过场。
6. **F：实测修订。** 逐曲真机验收、性能／缓存／存档故障测试、正常首见全流程时长测试；不足六小时就增加有意义的可玩内容，不加等待。

### 验收矩阵

- 垂直切片至少 6 名未读剧本测试者；完整流程至少 12 名，电脑／手机各 6 名，覆盖音游新手／熟练玩家，另测降低恐怖与完整辅助路径。
- 先定义正常路径与统计方式，记录有效阅读、调查、解谜、演奏、过场，排除切后台、下载、休息和失败重试。
- 正常首见主线目标 360–480 分钟，中位数接近 420 分钟，12 名首见玩家至少 10 名落入目标区间，并报告最短／中位／最长与各项构成。辅助演奏不应显著削减内容量；速通与主动跳过内容另列，不能为凑数惩罚他们。
- 任一必经谜题遇到操作困难，三级提示与等价入口可到达；关键材料持久可复查，不依赖颜色／声音／瞬间文字。
- 所有原始曲目实际开谱与结算成功；流媒体时长只能支撑预算，不能代替引擎内时长、附加资产、授权与表现核验。
- 刷新、断网、退出、重复结算、存储配额不足、跨标签页和导入存档都不会破坏自由模式数据。
- 普通剧情选择不造成无提示的永久软锁；六种平行线顺序都能到终局。
- 所有过场可暂停／跳过／回看，并具有同等的证据摘要。
- 测试者能说清一项修复的好处与代价、一名角色的生活偏好、一处自己选择的后果，以及角色最后如何生活；不能只记住“世界是程序、我拿到了权限”。
- 正式实现阶段运行 `pnpm check`、`pnpm build` 与适用测试；本轮纯文档不把这些命令当作故事验证。

### 目前尚未验证，但不冒充已完成的事项

- 首见时长、对白质量与完整剧本，需要实际制作和试玩。
- 所有选定谱面在当前引擎内的视觉、音频同步、附加资产和难度，需要逐首开谱。
- 远程媒体可访问不等于新增传播授权；发布前核对署名与使用范围，不把音频剪入新视频或新素材包后擅自再分发。
- 专用仓库线索与冻结提交在实现／发布阶段创建；本轮没有推送、建远端分支或发布线索。
- 如后续要求配音、付费资源、云存档、外部社交互动或改变世界表现形式，属于新边界，必须先问用户。

本稿已明确主线起承转合、人物意愿、地图关系、音乐任务、墙外解法、结局和内容预算；未决定的实际制作与验证事实不会用虚构数字或资源替代。
